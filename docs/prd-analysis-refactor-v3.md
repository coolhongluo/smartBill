## 一、背景与问题

### 1.1 现状

当前分析模块（v2）已建立「数值由代码计算、LLM 只负责判断与表述」的架构：
所有统计由 `bill-stats.js` 完成，模型通过 11 个 function-calling 工具取数，
输出经数值对账护栏校验，LLM 不可用时自动退回纯代码模板。

### 1.2 问题

| # | 问题 | 影响 |
|---|---|---|
| P1 | **同比缺失**：数据窗口仅 6 个月（`ANALYSIS_MONTHS = 6`），拉不到去年同月 | 用户无法回答「今年十月比去年十月花得多吗」 |
| P2 | **环比只有总额**：`calcMonthOverMonth` 只算总支出环比 | 用户不知道「多花的钱去哪了」，缺少类目归因 |
| P3 | **周期分析浅**：`calcRecurringPatterns` 只识别周期与频率，无金额稳定性、无记账频率画像 | 「每周买菜一次每次 45 元」这类高频小额画像无法表达 |
| P4 | **补记盲区**：账单日期与实际记账时间的差异从未被利用 | 集中补记用户的「日均」口径失真，分析结论可能误导 |
| P5 | **无异常视角**：单笔离群、类目突增无任何检测（`median()`/`cv()` 已写好但闲置） | 一笔 800 元的冲动消费淹没在「餐饮共 1200 元」里 |
| P6 | **洞察无结构**：`insights` 是纯字符串数组 | 前端无法分区渲染（异常/趋势/建议混排），推送无法按类型筛选 |

## 二、目标与非目标

### 2.1 目标

1. 用户在分析页能获得**五个维度**的消费分析：本月画像、对比分析（环比+同比+归因）、周期分析、异常信号、消费节奏。
2. 所有数值结论**可追溯**：每个数字来自统计代码，模型表述与工具返回值一致（护栏对账）。
3. 输出结构化且**向后兼容**：旧版本前端不改造也能正常渲染。
4. 诚实降级：数据不足时明说「基线不足」，不硬算、不编造。

### 2.2 非目标（本轮明确不做）

| 项 | 原因 |
|---|---|
| 订阅清单 + 续费预告独立卡片 | 本轮聚焦数据维度扩展；周期识别增强会顺带返回稳定性指标，订阅视图留待下版本 |
| 收入/结余/储蓄率分析 | 产品当前为纯支出记账，无收入数据模型；待产品侧支持后再立项 |
| 预算达成率 | 无预算功能，同上 |
| 改变「数值由代码计算」的架构原则 | 该原则是模块立身之本，明确保持不变 |

## 三、用户与场景

- **目标用户**：持续记账 ≥ 1 个月的家庭用户（「随口记」主力人群）。
- **核心场景**：
  - S1 用户记完账，打开分析页想看「这个月花得怎么样」→ 本月画像 + 对比分析。
  - S2 用户觉得这个月花得多，想知道「多在哪」→ 分类目环比 + 驱动因素分解。
  - S3 老用户（记账 ≥ 13 个月）想知道「比去年这个时候呢」→ 同比。
  - S4 用户想发现「自己没意识到的消费习惯」→ 周期分析 + 节奏画像 + 异常信号。
- **触发方式**（沿用现有机制，不改动）：
  记账成功后异步触发 / 用户点「立即分析」/ 每日定时批量增量（`dailyInsight`）。
  分析页只读已落库结果（`categoryBreakdown`），毫秒级返回。

## 四、功能需求

### F1 本月画像（现有增强）

维持现有输出（总额、笔数、记账天数、日均、最大单笔、类目占比 Top N、刚性/半刚性/弹性三分），
新增一项：

- **FR1.1 二级类目下钻**：Top 类目占比卡支持展示一级类目下的二级构成（如「餐饮 → 在家吃饭 / 外出就餐」），数据来源 `categoryPath`。

### F2 对比分析（本轮核心）

#### FR2.1 环比（总额 + 分类目）
- 本月 vs 上月总支出环比（现有能力保留）。
- **分类目环比**：每个一级类目本月 vs 上月，输出变化额与变化率。
- **驱动因素分解**：总支出变化额按类目拆解，标注 Top 驱动类目。
  示例：「本月多花 512 元，其中 410 元来自购物（+3 倍）、180 元来自餐饮，交通少花 78 元」。

#### FR2.2 同比（新增）
- 本月 vs 去年同月总支出，输出变化额与变化率。
- **数据前提**：分析窗口 6 → 13 个月（`ANALYSIS_MONTHS = 13`）。
- **诚实降级**：去年同月无账单或有效笔数 < 3 笔时，返回 `hasYoYBaseline: false`，
  前端显示「记账未满一年，明年此时可看同比」——**禁止**用其他基线冒充同比。
- 同比同样支持类目维度（口径与分类目环比一致）。

#### FR2.3 趋势
- 保留近 3/6 个月趋势；新增 12 个月档（`get_trend` 的 `monthCount` 上限 12 → 13）。
- 支持单类目趋势下钻（`get_trend` / `get_category_share` 传 `category`）。

### F3 周期性支出分析（「同一支出的记账周期」）

产品确认本轮取**三层含义**，全部实现：

#### FR3.1 周期性支出识别（现有增强）
- 识别周/月周期消费，输出：周期标签、次数、单次均价、月总额。
- **新增金额稳定性**：每个周期项输出变异系数（`cv()`），并在文案中体现：
  - `cv < 0.2` →「金额稳定」（如房租 3500 元/月）
  - `cv ≥ 0.5` →「金额波动大」（如每周买菜 80~200 元）

#### FR3.2 同类目记账频率（新增）
- 对一级类目输出：平均记账间隔（天）、单次均价、月记账次数。
- **消费模式标签**（规则判定，非模型判定）：
  - 高频小额：间隔 ≤ 3 天且单次 < 50 元（如「买菜每 2 天一次、每次 38 元」）
  - 低频大额：间隔 ≥ 10 天且单次 ≥ 200 元（如「服饰每月 1~2 次」）
  - 普通频次：其余
- 笔数 < 3 的类目不输出频率画像（样本不足）。

#### FR3.3 补记行为分析（新增）
- **判定**：账单的记账日期（`createTime` 所在自然日）晚于账单日期（`date`）**次日及以上**，即视为补记。
- 输出：本月补记率（补记笔数/总笔数）、集中补记日（单日补记 ≥ 3 笔）。
- **口径修正**：补记率 > 40% 时，日均文案追加说明「按记账日计算日均可能失真，已按账单日期计算」。

### F4 异常信号（新增）

| 信号 | 判定规则（默认阈值，可配置） | 输出 |
|---|---|---|
| 单笔离群 | 某类目内单笔金额 > 该类目中位数 × 3，且类目笔数 ≥ 4 | 该笔日期、金额、类目、备注（如有） |
| 类目突增 | 分类目环比涨幅 ≥ 50% 且变化额 ≥ 100 元 | 类目、变化额、变化率 |
| 类目突降 | 分类目环比降幅 ≥ 50% 且变化额 ≥ 100 元 | 同上（作为正面信号呈现） |

- 阈值集中定义在 `bill-stats.js` 顶部常量区，带注释说明口径。
- **上限**：每次分析异常信号最多输出 3 条，按金额影响排序。
- **边界**：环比基线不存在（上月无数据）时，类目突增/突降**不判定**；单笔离群不受影响。

### F5 消费节奏画像（新增）

| 维度 | 输出 |
|---|---|
| 工作日 vs 周末 | 两区间总额与占比；周末日均高于工作日日均 2 倍时给出观察结论 |
| 月内分布 | 上/中/下旬各占总支出比例 |
| 月末突击 | 下旬占比 ≥ 45% 且下旬笔数 ≥ 5 时输出信号 |

- 节奏画像只进 `insights`（观察类结论），**不进 `savings`**（不给「少在月末花钱」这类空洞建议）。

### F6 结构化输出与前端展示

#### FR6.1 洞察结构（双写兼容）
`insights` 保持字符串数组不变（旧前端依赖），并行新增 `structuredInsights`：

```json
{
  "structuredInsights": [
    {
      "type": "anomaly",            // structure | comparison | recurring | rhythm | anomaly
      "text": "10月18日一笔 480 元的「购物」超过该类目中位数的 3 倍",
      "evidence": "get_anomalies: outlier/购物/480",
      "severity": "warn"            // info | warn | high
    }
  ],
  "insights": ["10月18日一笔 480 元的「购物」超过该类目中位数的 3 倍", "..."],
  "schemaVersion": 3
}
```

- `type` 与 `evidence` 由**代码生成或护栏校验**，模型只填 `text` 与 `severity`；
  `evidence` 必须含来源工具名，对账护栏校验 text 中的数字与该工具返回值一致。
- `severity` 判定参考：异常 → warn/high；对比/周期/节奏/结构 → info。

#### FR6.2 分析页展示（渐进迁移）
- **第一阶段（本轮后端）**：前端不改，读旧字段，功能无感知升级（同比/异常等新维度以文字形式混排在 insights 中）。
- **第二阶段（前端排期）**：分析页分区渲染——
  - ⚠️ 异常区（severity ≥ warn 置顶）
  - 📊 对比区（环比卡 + 同比卡 + 驱动归因，同比无基线时显示引导文案）
  - 🔁 周期区（周期支出 + 频率画像）
  - 📅 节奏区（工作日/周末、月内分布）
  - 💡 建议区（savings，现有）

## 六、降级与护栏（沿用 + 扩展）

1. **刚性支出铁律不变**：房租、学费、药品等刚性类目禁止出现在 `savings`，异常信号只作「事实陈述」不作「节省建议」。
2. **B 方案不变**：无备注类目给通用建议时 `confidence: "low"`，reason 说明依据是类目而非场景。
3. **数值对账护栏扩展**：校验范围从 `savings.amount` 扩展到 `structuredInsights[].text` 中的数字（与 evidence 指向的工具返回值比对）。
4. **LLM 兜底模板扩展**：`insight.agent.fallback()` 增补对比、异常、节奏三个模板段落，降级时新维度仍有结论（数字全部来自 stats）。
5. **空数据 / 基线不足**：区分「没记账」（`isEmpty`）、「上月无数据」（`hasBaseline: false`）、「去年无数据」（`hasYoYBaseline: false`）三种状态，前端分别引导。

## 七、非功能需求（NFR）

| 项 | 要求 |
|---|---|
| 单次分析耗时 | ≤ 15 秒（原基线 10 秒；数据翻倍 + 轮次 3→4，实施后实测，超限则优化工具合并） |
| `dailyInsight` 批量 | 40 秒硬预算不变；单用户耗时重测后自动收缩每批人数（现有时间预算机制，无需改代码） |
| Token 预算 | 输出 1400 → **2000**，总 1800 → **2400**（结构化输出变长；实施时按实际 P95 调） |
| 工具规模 | 11 → ≤ 15 个；工具轮次上限 3 → **4**；对比类维度合并为 `get_comparison` 单工具，禁止按维度碎片化加工具 |
| Prompt | 新增工具入铁律表的同时做一次**分节精简**，总长度不超过现版 110% |
| 兼容性 | 双写期间旧前端零改造可用；已落库旧 schema 文档可正常渲染（新字段缺省） |
| 可回滚 | `LLM_ENABLED=false` 一键回规则版语义保持；schemaVersion 支持前端按版本分支 |
| 成本 | 同比使拉取量翻倍，仅统计层内存/CPU 增加，LLM 调用次数不变；批量任务沿用「按需增量」，不做全量重算 |

## 八、验收标准

### 后端（analysis-svc / harness）
- [ ] 窗口 13 个月：账单跨度 ≥ 13 个月的用户，同比结果与手工核算一致；
- [ ] 账单跨度 < 13 个月：`hasYoYBaseline: false`，不出现编造的同比数字；
- [ ] 分类目环比 + 驱动分解：构造用例（购物+410、餐饮+180、交通-78），文案归因数字与 stats 一致；
- [ ] 异常检测三项规则各有单测（含阈值边界：恰好 3 倍中位数、恰好 50% 涨幅）；
- [ ] 补记判定：`createTime` 与 `date` 差 1 天不计补记、差 2 天计补记，单测覆盖；
- [ ] 频率画像：笔数 < 3 的类目不出画像；高频小额/低频大额标签判定单测通过；
- [ ] 护栏：构造模型输出编造数字（如同比写了 300%），`structuredInsights` 对账拦截生效；
- [ ] 降级：`LLM_ENABLED=false` 时新维度模板结论齐全且数字正确；
- [ ] 双写：`insights`（字符串）与 `structuredInsights[].text` 内容一一对应，`schemaVersion: 3`；
- [ ] 旧已落库文档（无新字段）经 `categoryBreakdown` 读取，前端渲染不报错。

### 性能
- [ ] 13 个月、单月 ≤ 200 笔规模下，`computeInsight` 全程 ≤ 15 秒（P95）；
- [ ] `dailyInsight` 单批不超时（deferred 机制触发即算通过）。

### 前端（第二阶段）
- [ ] 五分区渲染正常，异常区置顶；
- [ ] 同比无基线用户看到引导文案而非空白卡。

## 十、风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| 13 个月拉取导致耗时/内存超限 | 分析变慢、批量任务缩水 | M1 实测；必要时同比基线改为独立轻查询（仅去年同月聚合值） |
| Prompt 变长稀释模型注意力 | 工具漏调、规则违反 | 分节精简 + 抽检调对率；不达标继续合并工具 |
| 结构化输出 token 超预算 | 输出被截断、JSON 解析失败 | 预算上调 + `structuredInsights` 条数上限 6 |
| 双写期数据不一致 | 新旧字段内容对不上引发用户困惑 | `structuredInsights[].text` 由 `insights` 同源生成，禁止两条生成路径 |
| 新维度结论冒犯用户（如异常被理解为「乱花钱」） | 用户流失 | 文案基调定为「陈述事实 + 提供视角」，禁用评判性措辞；review 全部模板文案 |

## 附录 A：术语

| 术语 | 定义 |
|---|---|
| 环比 | 本月 vs 上月 |
| 同比 | 本月 vs 去年同月 |
| 驱动因素分解 | 总支出环比变化额按类目拆解，找出主要涨跌来源 |
| 补记 | 记账日期晚于账单日期次日的记账行为 |
| 刚性/半刚性/弹性 | `category-compressibility` 的三级可压缩性分级，决定类目能否进入节省建议 |
| B 方案 | 无备注时允许给低置信度通用建议的策略 |
| 双写 | 同一次计算同时输出旧字段（字符串 insights）与新字段（structuredInsights） |
