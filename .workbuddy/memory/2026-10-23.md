# 2026-10-23

## 修复：云端与本地代码版本不一致

### 现象

前端抛 `云端与本地代码版本不一致（云端 xxx，本地 20261023-01）`。

### 根因

`npm run prepare:cf` 在 10-21 之后没再跑过，只同步了 analysis-svc 一个：

| 位置 | 版本戳 |
|------|--------|
| 源 `cloudfunctions/shared/` | 20261023-01 |
| analysis-svc 副本 | 20261023-01 |
| asr/bill/category/user-svc 副本 | **20261021-04** |

`bill-svc/shared/db/index.js` 也缺了 `listPendingInsightUsers`（定时任务那批新代码）。

云端跑的是 bill-svc 的 10-21 副本 → 云端返回 20261021-04，
与本地期望 20261023-01 **日期段不同** → 前端走 `assertCodeVersion` 的
「日期不同」分支，抛的是「请确认两端代码来自同一版本」——
**引导方向完全指错**，用户不知道该去跑 prepare:cf。

### 修复

1. `npm run prepare:cf` —— 5 个副本全部对齐 20261023-01（21 个文件，含 node_modules 副本）
2. preflight [2/8] 增加**内容级漂移守卫**（tools/preflight.js）

### 新增守卫（tools/preflight.js [2/8]）

原有检查只看 `node_modules/shared/agent-harness/index.js` **存在**——
副本内容再旧它也通过。现在补两项：

- **逐文件 sha1 哈希比对**：源 vs 每个云函数的 `shared/`，
  报告「缺 X / 旧 X / 多 X」，落后即判失败（hardFail）
- **副本 CODE_VERSION 必须 == 源 CODE_VERSION**

已用人为漂移验证：把 bill-svc 副本改回 20261021-04 →
旧检查仍报「均已同步」，新检查报「副本落后于源（1 个文件不同）」+ 退出码 1。

### 教训

**「文件存在」≠「内容是最新的」。** shared 的多副本结构（每函数一份）
天然会漂移，而存在性检查对漂移完全失明。

**版本戳不一致时，先查本地副本，再怀疑云端。**
本地 `shared/` 与各函数副本不同步时，云端返回的是旧版本号——
看起来像「忘了部署」，实际是「忘了同步」。
前端那句「请确认两端代码来自同一版本」不区分这两种情况，容易把人带偏。
