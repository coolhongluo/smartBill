## 修版本对账的方向判断错误（版本 20261018-15）

用户截图报错：`云端代码版本过旧（云端 20261018-14，本地 20261018-11）`
—— 用户问「这个校验是否有问题」。

**问题确实存在，而且严重：文案与事实相反。**
云端 14 > 本地 11，说明**云端更新**（云函数已部署，本地小程序包是旧的），
但提示却说「云端过旧、你的改动还没上传，请部署云函数」——
**引导方向完全相反**，会让人去部署一个本来就不旧的云函数，
然后继续困惑「我明明部署了怎么还提示过旧」。

**根因**：`assertCodeVersion()` 只判断 `remote !== EXPECTED`，
不一致就一律报「云端过旧」，**从不判断谁更新**。

**修复**：
- 解析版本号为 `{date, seq}`，seq 用 `parseInt` 按数字比较
  （字符串比较下 `'20261018-9' > '20261018-14'` 成立，会判反）
- 云端旧 → 「请上传并部署云函数」
- 云端新 → 「请重新编译小程序，用新预览码扫码进入」
- 日期不同（跨天）→ 只陈述「两端版本不一致」，不给方向性建议
- 老版本云函数无 codeVersion 字段 → 不拦截（保持原有行为）

**实测 6 条路径全部正确**：一致 / 云端旧 / 云端新 / 不同日期 / 无字段 / 序号一位数。
preflight 新增 2 项守卫防退回去。

**元教训**：对账类校验必须**区分方向**，不能只判「相等与否」。
只判不等的对账，在两边版本不一致时有一半概率给出反向建议——
而错误建议比没有建议更糟，因为它会让人执行错误操作。

## 类目选择器三个 bug（三级联动串数据 + 点不动/滚不动）

用户截图：选择类目弹层里「二级=衣物鞋帽」旁边却挂着「买菜/肉蛋/水产」，
且底部几项点不到、列表拖不动。

**先验证再改**：本地 require `shared/util/category-preset.js` 跑结构校验——
12 一级 / 166 二级 / 109 末级，父子关系无孤儿。**类目库数据本身没问题**，
不要一看到截图就怀疑数据，是前端状态与布局的锅。

**根因 1 · 三级列表残留**
`onPickL1` 只重置了 `curL2` 和 `catLevel2`，**没清 `catLevel3`**。
切一级后旧末级仍渲染在右侧。更严重的是 `resolveSelectedCategory()`
会拿残留的 `catLevel3[0]` 提交——**账会真的记到错的类目上**。
修复：切一级时一并清空 + 重置滚动；提交时要求 `curL1>=0 && curL2>=0` 才认三级。

**根因 2 · 底部被原生 tabBar 压住**
`.cat-sheet` 是 `72vh` 且 `padding: 32rpx`，铺到屏幕底。
原生 tabBar 浮在页面之上，盖住面板最后一行 → 底部项点不到、拖不动。
修复：底部留 `calc(110rpx + env(safe-area-inset-bottom))`。
**教训：页面有原生 tabBar 时，任何贴底的 fixed 弹层都要预留 tabBar 高度。**

**根因 3 · flex 高度不确定导致 scroll-view 滚不动**
`.cat-lv2 { max-height: 40% }` 在 flex 容器里百分比基准解析不可靠；
`.cat-lv1` 作为 flex 子项默认 `min-height: auto`，内容撑破容器。
两者叠加 = 有内容但没有可滚动区域。
修复：二三级改 `flex: 1 1 0` + `min-height: 0`，一列补 `min-height: 0`。
**通用铁律：flex 子项里放 scroll-view，必须显式 `min-height: 0`，否则永远滚不动。**

顺带：二三级都是白底无标题，视觉上混成一坨 → 加 sticky 分区标题
（「二级分类」/「选一个具体项」）；二级若无末级则直接提交，避免卡住。

只改前端三文件，**不涉及云函数，无需重新部署**。
`node --check` + `npm run check:ui`（24 个事件处理器全部有对应方法）通过。
