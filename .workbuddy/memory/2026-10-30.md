# 2026-10-30

## 明细页编辑功能：支持编辑所有字段

用户需求：「明细界面增加编辑功能，支持编辑所有字段」。

### 现状

明细页 `onBillTap` 是占位符（toast「编辑功能待 P1 接入」）。
云端 `handleAmend` 存在但只支持 `amountCent/categoryId/date/note/delFlag`。

### 踩到的三个坑

**1. `amend` 只改 categoryId 不改 categoryPath → 统计口径错乱**

统计侧（`bill-stats.js`）**完全依赖 categoryPath** 分组：
- `top = split('/')[0]` → 占比、刚性判定
- `leaf = split('/').pop()` → 末级类目分组
- `second = split('/')[1]` → 餐饮的「在家吃饭/外出就餐」

早期 amend 只写 `categoryId`，`categoryPath` 保持旧值 →
界面显示的还是旧类目、统计也按旧类目算，**但用户明明改了类目**。

**修法**：`categoryId` 与 `categoryPath` 必须成对写入。
且**不信任前端传的 path** —— 预置类目一律按 id 反查
（新增 `preset.pathOf(id)`），只有自定义类目才用前端传的 path。
理由：前端传错 path 就会写入与 id 不匹配的 path，统计立刻错乱。

**2. `amend` 完全没有校验**

`handleManual` 有严格校验（正数、整数分、不超上限），
`handleAmend` 却**一个校验都没有** —— 负数、0 元、超大金额都能直接写进库。

补齐：金额正数/整数分/上限、日期格式、拒绝未来日期、
账户枚举校验、备注长度、类目成对。

⚠️ **校验必须写在「本地环境跳过落库」的早退之前**。
否则本地跑测试时全部走早退分支，校验逻辑一次都没执行过 ——
测试全绿但校验其实没生效。（我第一版就写错了，e2e 立刻暴露。）

**3. 前端全量提交字段 → 自定义类目的账目改不了**

前端若总是提交 `categoryId`，而用户的自定义类目 id 不在预置类目库里，
云端反查不到 path 就可能拒绝这次编辑 —— **而用户只是想改个金额**。

**修法**：前端只提交**真正改动过**的字段（与原值比较后才带上）。
未改的不重发：既不白跑一次云函数，也不覆盖掉并发改动。

### 分析结论的过期判定（连带修的 bug）

`listPendingInsightUsers` 用 `b.createTime` 判断分析是否过期，
但**编辑只改 `updateTime`** → 用户把 100 改成 500 元后，
分析页会一直展示基于 100 元的结论（占比、节省建议全错）。

**改**：`max(createTime, updateTime)` —— 语义是「账单最后一次变动时间」。
定时任务与页面的判据必须一致，否则会出现
「定时任务认为过期、页面却显示为最新」的割裂。

同时给 `readInsight` 加了 `isOutdated` 字段，页面显示过期提示条。

### 类目选择器抽成组件

三级联动选择器约 150 行 JS + 120 行 WXML + 170 行 WXSS 原本写死在 index 页。
明细页编辑面板也需要 → 复制一份就是**第二个真相源**。

抽成 `components/cat-picker/`（与已有的 `cat-create` 同一思路：
类目相关交互不依附于具体业务场景）。

组件对外只暴露两个事件：`select`（选中）/ `cancel`（关闭）。
组件内部有三条到达同一结果的路径（三级联动/搜索/新建后选用），
统一收敛成一个 select 事件 —— 父组件不该去反查组件内部状态。

额外能力：`initial-id` 属性让编辑时直接定位到用户当前所在的层级。

### 测试踩到的坑

**契约测试的正则不能想当然**：
- 「只提交改动过的字段」：实际写法是花括号块 `if (...) { payload.x = ... }`，
  写成 `if (...) payload.x` 的正则永远匹配不上
- 「categoryId 与 path 成对提交」：实际是 `payload.categoryId =`（赋值），
  我写成 `categoryId:`（对象字面量）→ 误报
- 「校验早于本地早退」：handleAmend 里有**两处**「本地环境未接入数据库」
  （delFlag 分支一处），用 `indexOf` 首次匹配会定位错

**通用教训**：契约测试的正则必须对齐**实际代码形态**，
否则测试要么假失败要么假通过 —— 假通过最危险。

### 补：数据绑定守卫自己也漏了（验证时才发现）

加强后的守卫第一版**只查 wx:for 循环体内的绑定**，
把 `{{editNote}}` 拼错成 `{{editNoteTypo}}` 它完全无感 ——
而编辑面板的金额/备注/日期全在循环外。

**教训：守卫本身也要用「注入 bug」的方式验证**，不能只看它跑绿。
现在覆盖两层：
① 循环体内的 `item.xxx` / 自定义循环变量（`bill`、`group`）
② **循环体之外**的直接绑定（`{{editAmount}}` 这类）

另外两处也要注意：
- 列表名可能是**带点的路径** `{{result.candidates}}` —— 只匹配纯标识符会漏掉
- 绑定可能是**三元** `{{a === b ? 'x' : ''}}` —— 只匹配 `{{字段}}` 会漏掉三元里的字段
- 提取字段前必须**剔除字符串字面量**，否则 `'x'` 会被当成字段名
- `wx:for-item` 可自定义循环变量名，不能只认 `item`

验证：注入 `{{editNoteTypo}}` → 立刻报
「绑定了 editNoteTypo，但整条数据链路上都找不到这些字段」。

### 教训：写文件时别用 shell heredoc 拼正则

本次用 `node -e` 内嵌正则写文件，**反斜杠被 shell 吞掉**，
`/\{\{...\s*\}\}/` 变成 `/{{s*...}}/`，且模板字符串里的 `{{` 断了字符串。
报错是 `SyntaxError: missing ) after argument list` —— 定位不难但费时间。

**正确做法**：含正则/模板字符串的代码用 Edit/Write 工具写，
不要塞进 shell 命令行。

## 类目管理：新增三级分类选不了二级

用户报：「类目管理中，新增自定义分类中 新增三级分类无法选择正确的二级分类项目」。

### 两个缺陷叠加，全程零报错

**① 布局塌陷（主因）**

`.cc-card` 只有 `max-height: 80vh` —— 容器高度**不确定**，
flex 分配就没有基准。`.cc-l2-scroll` 写的是 `flex: 1; min-height: 0`，
`min-height: 0` 允许它被压到 0 高度。
一级 chips 越多（预置 12 + 自建一级），二级候选区被挤得越小：

| 一级数量 | 二级候选区高度 | 二级内容需要 |
|---|---|---|
| 12 预置 | 51px | 115px（要滚动才看全）|
| 12 + 5 自建 | **0px** | 115px |
| 12 + 10 自建 | **0px** | 115px |

**浏览器实测**（375×667，用 Playwright 复刻 WXML+WXSS 量测）：
12 预置 + 5 自建时 `.cc-l2-scroll` 高度 = **0px** → 二级完全看不见、点不到。
「无法选择正确的二级分类项目」= **连选都选不了**。

注意：`.cc-chips` 本身**不是** flex 子项（它在 `block wx:else` 里），
真正吃空间的是 `.cc-l1-scroll` —— 我给一级 chips 也套了 scroll-view + max-height。

**修法**（仿 cat-picker 的 `flex: 1 1 0` 链）：
- `.cc-card.is-pick { height: 80vh; }` —— 选父类时给**确定高度**（有基准）
- `.cc-l1-scroll { flex: 0 0 auto; max-height: 240rpx; }` —— 一级限高，不吃卡片
- `.cc-l2-scroll { flex: 1 1 auto; min-height: 140rpx; max-height: 320rpx; }` —— **min-height 是硬下限**
- WXML 卡片加 `{{level === 1 ? '' : 'is-pick'}}`

修完实测：二级区 128~160px，**不再随一级数量变化**。

**② 虚拟分组混入候选**

category-svc 的树里，早期「挂在一级下的末级」收在虚拟分组
`custom_{topId}`（name=「自定义」，**customGroup=true**）里。
它是展示容器，**不是二级类目**：
- 选它当二级 → 云端 `resolveNode` 找不到 → 报「上级必须是二级类目」
- 它没有 custom 标记 → 界面上也看不出跟真二级有什么区别

原 `l2OptionsOf` 直接 `map(t.children)` 全都收进来了。
修法：过滤 `customGroup`。

### 教训

**① 「选了但选不中」和「选了但选错」要分开查**
用户说「无法选择正确的二级分类项目」，字面像「选错了」，
但实测是「**根本选不到**」（区域 0px）。先复现界面真实高度再下结论。

**② 布局 bug 必须用真实浏览器量，不能靠读 CSS 猜**
`max-height` 的容器 + `flex:1` + `min-height:0` 组合，
纯读代码看不出塌陷。用 Playwright 复刻 WXML+WXSS 量 getBoundingClientRect，
一眼看到「二级区 = 0px」。
（Playwright bundled chromium 没装，用 `chromium.launch({channel:'chrome'})` 走系统 Chrome。）

**③ 守卫的正则要断言「值 > 0」，不能只断言「有这条」**
第一版写 `/min-height\s*:\s*\d/` —— `min-height: 0` 也匹配！
而 **0 恰恰就是原始 bug**。注入回退测试时发现抓不住，改成断言数值 > 0。

**④ 守卫自己也要用「注入 bug」验证**
四个缺陷（min-height→0、删 is-pick、不过滤 customGroup、一级不限高）
逐个注入回退，确认测试都能报错、恢复后全绿。

**⑤ 抽成纯函数才测得动**
原逻辑写在组件方法里，只能靠搭 harness 模拟。
抽到 `utils/cat-tree.js` 后，`require` 进来直接断言，
顺带让「虚拟分组过滤」这条规则有了单一落点。

## 修：编辑对话框金额错误 + 移除「支付方式」

用户反馈两条：① 编辑对话框金额错误 ② 不需要支付方式。

### 根因①：回填时把「展示用字符串」当数值用

`groupByDate` 里同一份金额存了**两个字段**：

```js
amount:     formatCent(b.amount),   // "¥120.50" ← 展示用字符串
amountCent: b.amount,               // 12050      ← 原始整数分
```

`onBillTap` 回填时传了 `bill.amount`：
```js
editAmount: yuanInput(bill.amount)   // ✗ 传错了
```

`yuanInput` 里 `Number("¥120.50")` = **NaN** → 被 `|| 0` 兜成 `0`
→ 打开编辑面板金额显示 **0**，直接点保存还会报「请输入有效金额」。

**最坑的是零报错**：面板正常打开、其他字段正常回填，
只有金额是 0。若当时没有测试，用户会以为「编辑功能坏了」。

**修**：`yuanInput(bill.amountCent)`。

**教训（已写进 MEMORY）**：
**同一份数据在两个字段上长得像，名字就得说清单位**。
`amount` / `amountCent` 这种命名太接近，早晚有人传错。
理想做法是让类型本身区分（如 `amountCents` vs `amountDisplay`），
或在转换函数入口做一次断言（`Number.isInteger` 检查）。

### 顺带修掉一个浮点精度隐患

原保存逻辑 `Math.round(parseFloat(str) * 100)`：
`8.115 * 100 = 811.4999999999999` → `Math.round` → **811**（少一分钱，用户完全看不出）。

改为新增 `yuanToCent(str)`：**按字符串逐位解析**，全程整数运算：
```
整数部分 × 100 + 小数前两位 + 第三位四舍五入
```
且非法输入返回 `null`（区别于「真的 0 元」），让前端能给出准确提示。

### 根因②：支付方式整块移除

前端编辑面板不再暴露「支付方式」。但**云端能力保留**：
`handleAmend` 仍接受 account 参数（ASR 链路会写入账户），
只是前端不提供入口。改了云端就得重新部署，而用户明确说不需要这个功能。

**删干净的部分**（避免死代码）：
- `detail.js`：`editAccount` / `accountOptions` / `onPickAccount` / payload 里的 account 分支
- `detail.wxml`：账户选择区块 + 列表里的账户标签
- `detail.wxss`：`.edit-accounts` / `.edit-account` / `.bill-meta-sep`
- `format.js`：`ACCOUNT_OPTIONS` / `accountLabel`（前端不再需要）
